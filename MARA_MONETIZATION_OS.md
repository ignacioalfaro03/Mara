`ATTENTION → FIRST VALUE → RETURN → FIRST PAYMENT → SECOND PAYMENT → CONTRIBUTION MARGIN`

## 2. Business architecture

Mara is not one product. It is one character business with coordinated monetization layers.

### Attention layer

**Instagram / social** creates discovery through simple, high-retention story arcs.

Primary grammar:

`HOOK → CONFLICT → INCOMPLETE INFORMATION → CLIFFHANGER`

Social should not behave like an adult-content catalogue. It should make users want to know what happens next.

### Relationship layer

**DM / web experience** converts curiosity into interaction, memory and continuity.

### Retention layer

**Memory + World + recurring story consequences** create reasons to return.

### Variable-cost recovery layer

**Prepaid chat** funds model inference before consumption.

### Margin layer

**Preproduced audio / image / video / Drops** are created once and sold repeatedly.

### AOV layer

**Story Passes / bundles / collections** increase average order value without proportionally increasing marginal cost.

### High-ticket layer

**Caprichos** allow participation in concrete Mara goals that can later become persistent World Assets.

### Ownership layer

**Vault / My History** preserves purchased/unlocked experiences and real participation history.

### Repeat-spend layer

**World consequences + new arcs + callbacks** convert one purchase into future purchase opportunities.

The business loop is:

`ATTENTION → EXPERIENCE → FIRST VALUE → RETURN → MICRO PURCHASE → CONTENT PURCHASE → CAPRICHO → PAYOFF → WORLD CONSEQUENCE → RETURN → REPURCHASE → HIGHER LTV`

## 3. Permanent unit-economics doctrine

These are product laws, not suggestions:

- **FREE != UNLIMITED**
- **PAID != UNLIMITED**
- **NO NEGATIVE BALANCE**
- **NO POSTPAID AI CONSUMPTION**
- **NO PROVIDER CALL WITHOUT ALLOWANCE**
- **NO USER GETS UNBOUNDED VARIABLE COST AT MARA'S EXPENSE**
- **CREATE ONCE → SELL MANY TIMES** whenever media can be preproduced
- every real-cost entitlement needs a defined cost ceiling
- every plan/pack needs server-authoritative allowance
- spending guards must exist before scale

For every variable-cost conversation request:

`ALLOWANCE CHECK → RESERVE → PROVIDER CALL → SETTLE → DECREMENT → RELEASE UNUSED RESERVE`

If allowance is insufficient, the provider is never called.

Commercial UX must not expose raw tokens as the product. The user buys continued access or a defined experience; the backend meters the economics.

# REWARD ENGINE

## 18. Reward Engine contract

A confirmed purchase/contribution may trigger a **bounded, deterministic and guaranteed product payoff**.

Money may buy:

- content;
- performance;
- access;
- priority/capacity where operationally real;
- a digital reward;
- an approved adult roleplay payoff;
- World consequence;
- collection/ownership;
- a concrete entitlement.

Money does not buy:

- baseline affection;
- forgiveness;
- relationship status;
- Mara staying;
- emotional superiority over another user;
- control over Mara outside the purchased product contract;
- safety/consent overrides.
