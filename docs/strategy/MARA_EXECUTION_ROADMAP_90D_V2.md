# GOAL

Prove that creators will use a Mara Creator Site as a direct destination for their audience and that Mara can convert audience activity into fulfilled commerce with repeat value.

# STAGE 0 — THESIS / SURFACE REALIGNMENT

- remove Mara Vera from canonical product positioning;
- remove World from public product language;
- establish `/<creator>` as canonical Creator Site direction;
- keep legacy internal identifiers only as compatibility debt;
- align Home, metadata, Creator OS and tests.

Gate: a new contributor can explain Mara in under 60 seconds without mentioning Mara Vera or Creator Worlds.

# STAGE 1 — CREATOR SUPPLY

Recruit/interview 10–20 creators/influencers, primarily people with an existing audience.

Capture:
- current audience channels;
- desired site use;
- products/experiences they would sell;
- current monetization stack;
- pain with existing link/profile/store tools;
- desired customization;
- privacy requirements if any;
- expected earnings threshold;
- willingness to pilot.
Success gate:
`JOIN PILOT → PUBLISH SITE → SHARE URL → RECEIVE REAL AUDIENCE ACTIVITY`

# STAGE 2 — CREATOR SITE PILOT

Pilot 3–5 creators.

Minimum creator capabilities:
- account/authorization;
- public site;
- creator identity;
- one CTA;
- one offer or demand surface;
- Creator OS visibility.

Minimum fan capabilities:
- open from social browser;
- understand creator/site instantly;
- act without learning Mara's backend concepts;
- return and retain history where consented.

# STAGE 3 — DEMAND PROOF

Validate:
- request creation;
- WANT;
- PLEDGE/WTP;
- COMMIT;
- clustering;
- demand → creator opportunity;
- opportunity → offer.

# STAGE 4 — COMMERCE / FULFILLMENT

Only after provider/compliance feasibility:
`DEMAND / INVENTORY → OFFER → PURCHASE → FULFILLMENT → HISTORY`

Digital/reusable fulfillment first.

# STAGE 5 — RETENTION

Prove:
`FIRST OUTCOME → RELEVANT NEXT ACTION → SECOND PURCHASE / SECOND MEANINGFUL ACTION`
