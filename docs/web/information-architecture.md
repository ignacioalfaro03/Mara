# Mara Vera — Web Information Architecture

## Role of the web

The website is the owned hub for **brand + conversion + analytics + compliance**, and later the relationship layer. It is not a secondary landing page.

## Primary journey

**Social → Home → Meet Mara / Premium intent → premium handoff → paid surface**

The web should minimize navigation and keep one obvious next action per screen.

## Home

Purpose: convert curiosity into qualified premium intent.

Required blocks:
1. Hero with Mara Vera and a concise character-led proposition.
2. Primary CTA into the premium path.
3. Secondary CTA to Meet Mara.
4. Small, clear AI-generated character disclosure.
5. Selected visual/story proof that establishes personality.
6. Premium tease without an overwhelming catalog.
7. Footer with legal/privacy/reporting surfaces.
8. 18+ gate before adult-oriented paths where required.

Avoid:
- SaaS dashboards;
- chat as the entire Home;
- generic “AI companion” copy;
- feature grids;
- excessive navigation.

## Meet Mara

Purpose: turn a visual impression into character interest.

Structure:
- short story/identity;
- behavioral traits;
- interests and recurring world;
- gallery/content moments;
- interaction style;
- transparent AI disclosure;
- boundaries;
- CTA to premium experience.

## Premium

Purpose: explain value and route the user to the authorized monetization surface.

Structure:
- one clear proposition;
- what access includes;
- categories of premium experiences;
- pricing hypothesis or external handoff when authorized;
- transparency around what is paid;
- explicit opt-in for higher-intensity experiences.

Do not create many tiers before data justifies them.

## Legal / compliance surfaces

- Privacy
- Terms
- AI disclosure
- Adult / age statement
- Acceptable use / boundaries
- Contact/reporting
- Data deletion/contact path when applicable

## Future readiness

The web architecture should later accept:
- first-party authentication;
- profile/preferences;
- relationship state;
- consent-based memory;
- payment/provider abstraction;
- personalized home/returning-user experiences.

These capabilities are future-ready, not MVP requirements.
