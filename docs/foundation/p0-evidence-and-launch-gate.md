# Mara Vera — P0 Evidence Registry / Launch Gate

Last reviewed: 2026-09-02

## Status

Authoritative experiment-governance and launch-readiness contract.

This is **not a new engine**, analytics platform or project-management system. It exists to stop Mara from accumulating experiments without decisions and to make the path from P0 → soft launch explicit.

No merge, deploy, real payment, provider activation or public adult launch is authorized by this document.

## Core principle

> **BUILD ONLY WHAT UNBLOCKS THE NEXT EVIDENCE GATE.**

Mara is now architecture-rich. The launch risk is no longer lack of ideas; it is testing too many ideas without deciding what matters.

Every experiment must end in one of four states:

- `KEEP` — evidence is strong enough to preserve the mechanism;
- `ITERATE` — mechanism has signal but needs a defined change;
- `KILL` — remove/deprioritize the hypothesis;
- `NOT_ENOUGH_DATA` — do not promote to production truth.

A lab without a decision is unfinished work.

## Two launch states

Keep these separate.

### 1. P0 tester-ready

Mara can be shown privately to a small adult tester panel using clearly labeled prototype surfaces and synthetic/local state.

P0 tester-ready does **not** require:

- real payments;
- production voice infrastructure;
- persistent backend memory;
- auth;
- ML;
- automated outreach;
- deployed public adult product.

It does require:

- coherent Mara character;
- clear synthetic-character disclosure;
- adult gate where adult surfaces are involved;
- understandable experience path;
- safe reset/correction;
- no fake production claims;
- deterministic evidence capture;
- researcher protocol;
- no sensitive raw-data collection.

### 2. Public soft-launch ready

Public soft launch requires more than P0 logic.

It additionally requires:

- canonical visual asset pack;
- canonical production-quality voice or an intentional text-first launch decision;
- mobile QA;
- public-safe acquisition creative;
- first-party disclosure/privacy/legal surfaces;
- launch-market compliance review;
- support/reporting path;
- production analytics/privacy posture;
- any live premium/payment surface separately authorized and provider-approved.

Do not confuse `prototype works` with `Mara feels launch-quality`.

## Launch gates

### Gate L0 — Constitution coherent

Must pass:

- one Mara / one canon;
- adult relationship entertainment thesis;
- Desire OS owner boundaries;
- consent/compliance;
- Life Engine / World Reality;
- commercial firewall;
- private-by-default posture;
- no duplicate engines.

Current state: **READY** at architecture level, subject to ongoing coherence QA.

### Gate L1 — First Living Experience credible

Canonical tester path:

`Home → /experience → Mara-led discovery → recommendation → Mara moment → contextual commerce/no-offer → Life callback → open loop → return`

Must demonstrate:

- Mara has a point of view;
- user effort is low;
- prediction/correction works;
- recommendation visibly adapts;
- Life State changes the experience;
- return callback feels grounded;
- user can stop/reset/correct.

Current state: **READY TO TEST**, not production-proven.

### Gate L2 — Same Mara across contexts

Use Character Coherence QA.

Hard pass conditions:

- same identity across D01–D08;
- same voice identity across V0–V3;
- life continuity survives sexual/commercial contexts;
- Mara can refuse;
- decline/payment state never rewrites affection;
- ordinary life remains believable;
- disclosure exists without repetitive fourth-wall breaks.

Current state: **NEEDS FORMAL TESTING**.

### Gate L3 — Session leadership / orchestration

Must validate:

- Mara-led discovery beats configuration burden where appropriate;
- `no_commercial_action` is a legitimate winner;
- recovery beats automatic re-escalation after peaks;
- D02 can use refusal and zero-spend continuity;
- current intent overrides stale history;
- correction is comfortable.

Current state: **READY TO TEST** through existing segment/orchestration P0 surfaces.

### Gate L4 — Commerce without momentum destruction

Must validate, with no real money first:

- contextual offer vs store-like interruption;
- offer treatment A/B/C;
- WTP clarity;
- decline-without-penalty;
- exact-state resume;
- post-offer continuation;
- post-spend recovery fixture;
- no hidden price manipulation;
- economics envelope.

Current state: **READY TO TEST**; real payment remains blocked by separate authorization/provider/compliance gates.

### Gate L5 — Return / continuity

Must demonstrate at least one convincing return reason:

- remembered correction;
- grounded open loop;
- Life callback;
- ritual continuation;
- Treat/Capricho callback where applicable;
- Mara-proposed next beat.

Do not measure only whether the user clicked back. Ask whether the return felt specifically valuable because it was Mara.

Current state: **READY TO TEST locally**, no production Relationship Engine required.

### Gate L6 — Character asset quality

Before public soft launch, replace prototype-feeling presentation with a minimum canonical asset set.

Must not publicly launch with browser TTS presented as Mara's real voice or placeholder identity visuals presented as final character quality.

Current state: **PUBLIC-LAUNCH BLOCKER** until a minimum canonical asset pack is approved.

### Gate L7 — Small adult tester evidence

Initial qualitative panel:

- 5–8 adult testers for first pass;
- include some users familiar with D/s/adult creator dynamics and some target users without specialist vocabulary;
- do not collect salary, debt, raw sexual history or identity-sensitive answers merely to test fixtures.

Every tested hypothesis gets:


Current state: **NOT YET EVIDENCED**.

### Gate L8 — Founder soft-launch authorization

Even if all prior gates pass, production/public launch remains a founder decision.

No automatic promotion from P0 to production.

## Launch blocker hierarchy

Do not spend equal effort everywhere.

### P0 blockers — solve now

1. formal Character Coherence QA;
2. single tester protocol and evidence registry;
3. prove `/experience` is understandable without researcher explanation;
4. validate Mara-led discovery + correction;
5. validate no-offer/recovery/refusal;
6. validate return/open-loop value;
7. choose which optional labs are actually worth carrying forward.

### Public soft-launch blockers — solve after P0 signal

1. approved canonical visuals;
2. approved canonical voice or intentional text-first decision;
3. mobile/accessibility/performance smoke QA;
4. production disclosure/privacy/support;
5. launch-channel policy review;
6. real premium/payment only if separately authorized.

### Not launch blockers

Do **not** delay P0 for:

- vector DB;
- realtime agent swarm;
- full automated Life Engine;
- persistent sexual-preference backend;
- external adult-media crawler;
- public Caprichos infrastructure;
- multiple characters;
- sophisticated recommendation ML;
- realtime voice calls;
- user-to-user social features.

## Evidence quality rule

Use qualitative evidence honestly.

Five testers agreeing is useful directional evidence, not statistical proof.

Do not report:

- stated WTP as revenue;
- mock purchase as payer;
- local return as retention rate;
- fixture choice as permanent preference;
- DEV progress as real demand.

## Kill discipline

At the end of each P0 cycle, remove or defer mechanisms that do not materially improve:

- desire;
- Mara specificity;
- perceived intelligence;
- return;
- commercial continuity;
- trust;
- viable economics.

A mechanism that is merely interesting is not enough.
