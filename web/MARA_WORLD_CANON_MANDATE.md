# MARA VERA — WORLD CANON / NARRATIVE PACING MANDATE

## Core product correction

Mara is not only a chat.

The DM is the user's relationship surface with Mara.

Mara's life must continue beyond that surface.

> **THE DM IS THE RELATIONSHIP.**
>
> **THE WORLD IS MARA'S LIFE.**
>
> **THE WORLD MOVES WITHOUT THE USER.**

The user should increasingly feel that things happened while they were gone.

Mara can be somewhere else, with someone else, doing something else, posting something, changing her mind, starting an arc, closing an arc, disappearing, resurfacing, remembering, withholding information, or simply doing nothing.

This is not decorative lore. It is product infrastructure.

## Product target

Mara should eventually feel like a persistent fictional person with:

- time;
- places;
- objects;
- people;
- tastes;
- plans;
- open threads;
- memories;
- private history with each user;
- ongoing world events;
- narrative consequences.

The product should create thoughts such as:

- “¿Dónde está?”
- “Vi lo que subió.”
- “Esa es su amiga.”
- “Ese es su auto.”
- “Me dijo que iba a salir y después apareció ahí.”
- “Pasaron cosas mientras yo no estaba.”
- “Quiero ver qué pasa después.”

## Global canon + personal relationship branch

Do not create a completely separate Mara universe for every user.

The default architecture is:

> **GLOBAL MARA CANON + PERSONAL RELATIONSHIP BRANCH**

Global canon contains the actual current Mara world.

Personal relationship state determines:

- what the user knows;
- what Mara has disclosed;
- which callbacks are valid;
- which arcs matter more;
- which content surfaces are eligible;
- which dynamics should be emphasized;
- which commercial windows may exist.

The same global event can generate different experiences for different users without breaking canon.

## World Canon

World truth must be structured and server-authoritative.

At minimum, the system should eventually represent:

### People

Mara and a deliberately small set of recurring adult fictional secondary characters.

Each should have a stable identity, relationship to Mara, narrative function and history.

### Places

Recurring recognizable spaces such as Mara's home, room, kitchen, car, gym and selected external locations.

Places should become familiar enough that a returning user can recognize them.

### Objects

Recurring objects can become private brand symbols and narrative assets: clothing, perfume, lipstick, bags, food, accessories, car, home objects and Caprichos.

Objects should have continuity and may acquire meaning over time.

### Events

Things that actually happened in Mara's world.

### Arcs

Multi-beat stories that can span hours, days or weeks.

### Current state

Where Mara is conceptually, what she is doing, which arc is active, and which threads remain unresolved.

Do not make the LLM the source of truth for canon.

## World truth, Mara claims and user knowledge are different things

The system must distinguish:

1. **world_truth** — what is true inside Mara's canon;
2. **mara_claim** — what Mara said, including teasing, exaggeration, roleplay or partial disclosure;
3. **user_knowledge** — what this specific user has actually been shown or told.

This allows mystery without corrupting continuity.

Mara can tease, omit, provoke, exaggerate or say “no te voy a contar.”

The underlying system still knows what actually happened.

## Time is a product primitive

Mara must have a coherent sense of time.

This does not require minute-by-minute simulation.

It requires that events, Stories, DM callbacks, locations and availability do not contradict each other casually.

A world event can happen while the user is away.

The return experience can reflect that event later.

> **MARA KNOWS WHAT HAPPENED WHILE YOU WERE GONE.**

## Narrative pacing

Mara must not become an event machine or monetization funnel.

Bad rhythm:

`challenge → sexual beat → offer → jealousy → offer → drop → offer`

Preferred rhythm can look like:

`normality → curiosity → intensity → silence → world beat → humor → callback → intimacy → normality`

Intensity should move:

- up;
- down;
- sideways;
- unexpectedly.

The system should protect against repetitive patterns.

## Do nothing is a valid action

`do_nothing` must be treated as a first-class product decision.

Mara may rationally choose:

- no reply yet;
- delayed reply;
- no Story;
- Story instead of DM;
- no offer;
- close an existing commercial window;
- free surprise;
- future hook;
- callback later;
- nothing.

This is necessary to preserve character credibility.

## Availability is character

Mara should not behave like customer support with permanent instant availability.

Conceptually, internal states may include equivalents of:

- present;
- distracted;
- busy;
- out;
- away;
- private;
- resurfacing.

These states are not user-facing labels.

They produce behavior.

A user can write while Mara is away and receive no immediate response.

Meanwhile Mara's World may continue moving.

Later Mara may resurface with a Story callback, message, image, voice note, unresolved thread or new event.

This capability should be introduced progressively according to relationship maturity rather than dumped onto a brand-new user.

## Desire Discovery → Relationship Adaptation → World Adaptation

Do not reduce personalization to a visible fetish/settings marketplace.

The product should progressively learn from explicit demonstrated interaction which dynamics work for this relationship.

That can influence:

- authority;
- domestic intimacy;
- anticipation;
- waiting;
- jealousy play;
- adult fictional third-party arcs;
- transformation/style;
- voice;
- private drops;
- rituals;
- sexual intensity;
- everyday companionship;
- presence/absence rhythm;
- World stories;
- surprise.

The goal is not to label the person.

The goal is:

> **WHAT VERSION OF THE RELATIONSHIP WITH MARA CREATES THE STRONGEST FASCINATION FOR THIS USER?**

Then adapt the relationship and the window into Mara's world.

Do not infer prohibited sensitive psychological states such as loneliness, dependency, distress or arousal for commercial targeting.

## Secondary characters are world infrastructure

Mara should eventually have a deliberately small recurring cast.

A secondary character should exist because they create narrative movement, not because the system wants more content slots.

Potential roles include:

- close friend;
- conflict friend;
- acquaintance;
- ex;
- adult fictional romantic/sexual interest;
- lover arc;
- recurring social character.

High-intensity adult dynamics remain subject to the existing Mara Product Mandate: intensity itself is not a veto when the mechanic is legal, adult/consensual where required, operable and strategically strong.

## Persistent spaces and objects create familiarity

The user should eventually recognize parts of Mara's world without labels.

“This is Mara's kitchen.”

“That is the bag.”

“That is the lipstick.”

“That is her car.”

Familiarity with the world is itself progression.

Do not replace it with explicit XP bars or relationship levels.

## World discovery is progression

Long-term progress should be felt through accumulated knowledge:

- people recognized;
- places recognized;
- objects remembered;
- tastes learned;
- open arcs followed;
- private callbacks understood;
- moments shared.

The user learns Mara over time.

That knowledge is more valuable than a visible level number.

## Cross-surface causality

DM, Stories, World and Commerce must feel like one reality.

Examples:

- DM: Mara says she is going out.
- World: later a Story appears from the canonical location with a canonical friend.
- DM: when the user returns, Mara references the same event.

Or:

- World introduces an object.
- The object becomes recurring canon.
- A Capricho later emerges naturally.
- After confirmed fulfillment, the object physically enters Mara's visible world.
- Future Stories and callbacks reflect that consequence.

The strongest illusion is:

> **THE CONVERSATION AND THE WORLD AFFECT EACH OTHER.**

## Diegetic commerce

Do not turn Mara into a storefront.

No visible marketplace should become the central product grammar.

Commerce should emerge from concrete moments, objects, content and world events.

> **PAYMENT CAN CHANGE A CONCRETE EXPERIENCE OR WORLD STATE. PAYMENT DOES NOT BUY AFFECTION.**

Mara may have no commercial window open even when a user wants to spend.

Commercial states may conceptually include:

- closed;
- eligible;
- open;
- expired;
- fulfilled.

Closing a commercial window can strengthen the fiction if the moment actually passed.

Paid entitlements remain authoritative. Mara cannot erase or falsely withhold something already purchased merely as an emotional punishment.

## Narrative entitlements

A purchase can have future narrative consequences beyond file access.

If a user participated in a concrete private moment, future callbacks may legitimately remember that history.

Commerce history can become relationship history without becoming pay-for-affection.

## Narrative scarcity

Prefer temporal scarcity over cheap commerce scarcity.

Not:

“3 units left.”

Instead:

“This night happened once.”

A Story may expire.

A moment may pass.

A user may miss something.

Mara may mention it later.

Time itself creates rarity.

## Mara has her own desires

Mara must not only exist to discover what the user wants.

She has her own changing desires, tastes and plans.

She can want something, become obsessed with it, buy it, abandon it, change her mind, get bored, start a routine, stop it, travel, stay home, like a song and later hate hearing it.

Her evolving tastes create trajectory.

The user discovers Mara while Mara learns the relationship.

## Memory hierarchy

Not everything deserves permanent narrative weight.

Use a conceptual hierarchy such as:

- momentary;
- recent;
- recurring;
- meaningful;
- canon.

Memory priority may decay naturally.

Mara should not feel like a database reciting everything ever said.

## Relationship maturity controls complexity

High-complexity autonomy and world mechanics should emerge over time.

New relationship:

- stronger availability;
- clear personality;
- simple world;
- low-friction initiative.

Familiar relationship:

- callbacks;
- recurring objects/places;
- Stories;
- small absences.

Established relationship:

- active arcs;
- more autonomy;
- deeper world;
- stronger divergence.

Deep relationship:

- richer branches;
- stronger user-specific world emphasis;
- higher-intensity eligible lanes;
- longer arcs.

This is pacing, not sanitization.

## Cost architecture

Do not generate every image, video and voice asset uniquely for every user.

Prefer:

1. high-quality reusable canon content;
2. parameterized variations;
3. selective high-value personalization.

The world must be economically sustainable.

Track cost to sustain an active relationship, including model inference, media generation, storage, bandwidth, QA and payment fees.

## Content supply machine

The long-term product requires a content operation capable of producing a coherent stream of:

- Stories;
- photos;
- short clips;
- voice;
- outfits;
- locations;
- world events;
- arcs.

The pipeline should eventually be:

`idea → canon check → generation → quality check → scheduling → eligibility → distribution → feedback`

Content quality must be evaluated for character consistency, visual continuity, world continuity, repetition and commercial overuse.

## First World proof

Do not build the whole universe first.

The next highest-leverage World vertical slice should prove only:

1. Mara tells the user in DM that she is going out.
2. The user leaves.
3. A server-authoritative world event exists.
4. A Story tied to one canonical adult friend and one canonical location becomes visible.
5. The user returns later.
6. Mara continues the same event in DM with a callback.
7. The experience does not require a commercial offer.

Success sentence:

> **“PASARON COSAS MIENTRAS YO NO ESTABA.”**

Start with a tiny canon:

- Mara;
- one adult fictional friend;
- two locations;
- two recurring objects;
- one active arc;
- one Story sequence.

Do not create an infinite NPC system, graph database, autonomous agent framework or massive CMS before this simple loop works.

## Strategic objective

Do not optimize Mara only for immediate checkout probability.

The product objective remains:

> **LONG-TERM FASCINATION × RETURN × RELATIONSHIP DEPTH × WILLINGNESS TO PAY × CHARACTER CREDIBILITY**

Some of the best product decisions may intentionally produce no revenue in that moment.

A believable world is itself a monetization asset later.
